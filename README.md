# Stream Notifier Bot

Автоматически присылает сообщение в Telegram-канал, когда начинается стрим
на Twitch и/или YouTube. Проверка идёт по расписанию через GitHub Actions
(бесплатно), без своего сервера.

Внешних зависимостей нет — скрипт использует только стандартную библиотеку
Python (`requirements.txt` не нужен).

## Как это работает

- Раз в 5 минут GitHub Actions запускает `stream_notifier.py`.
- Скрипт проверяет статус Twitch через официальный Helix API.
- Скрипт проверяет статус YouTube лёгким способом — без API-ключа и без
  квоты (см. раздел «Про проверку YouTube» ниже).
- Если канал только что стал live (а на прошлой проверке live не был) —
  бот шлёт в Telegram сообщение с картинкой-превью текущего кадра эфира.
- Текущее состояние («live / не live») хранится в `state.json`, чтобы не
  слать повторные оповещения каждые 5 минут, пока стрим идёт.

## Картинка в оповещении

Специального «захвата экрана» не требуется — и Twitch, и YouTube сами
генерируют превью прямо из трансляции:

- **Twitch**: Helix API уже отдаёт `thumbnail_url` вместе со статусом
  стрима — это живой кадр эфира, который Twitch обновляет каждые
  несколько минут.
- **YouTube**: используется стандартная превьюшка вида
  `i.ytimg.com/vi/<id>/hqdefault.jpg`, которая тоже обновляется по ходу
  трансляции.

Оба варианта отправляются в Telegram через `sendPhoto` с подписью (текст
тот же, что был раньше). Нюанс: сразу в первую секунду эфира превью может
быть ещё не сгенерировано (чёрный кадр или ошибка загрузки) — если
Telegram не смог получить картинку, скрипт автоматически подстрахуется и
пришлёт обычное текстовое сообщение, чтобы оповещение в любом случае
дошло.

## Шаг 1. Создать Telegram-бота и узнать chat_id канала

1. В Telegram напишите **@BotFather** → `/newbot` → следуйте инструкциям.
   В конце вы получите **токен** вида `123456789:AAExxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`.
   Это `TELEGRAM_BOT_TOKEN`.
2. Создайте Telegram-канал (или используйте существующий) и добавьте бота
   туда **администратором** (право на публикацию сообщений обязательно).
3. Узнать `chat_id` канала:
   - если канал **публичный** — просто используйте его юзернейм в формате
     `@your_channel`, это и есть `TELEGRAM_CHAT_ID`;
   - если канал **приватный** — отправьте в канал любое сообщение, затем
     откройте в браузере
     `https://api.telegram.org/bot<ВАШ_ТОКЕН>/getUpdates`
     и найдите в ответе `"chat":{"id":-100XXXXXXXXXX...}` — это число
     (со знаком минус) и есть `TELEGRAM_CHAT_ID`.

## Шаг 2. Получить доступ к Twitch API

1. Зайдите на https://dev.twitch.tv/console/apps → **Register Your Application**.
2. Название — любое, OAuth Redirect URL — `https://localhost`, категория —
   «Application Integration».
3. После создания приложения получите **Client ID** (`TWITCH_CLIENT_ID`) и
   нажмите **New Secret**, чтобы получить **Client Secret** (`TWITCH_CLIENT_SECRET`).
4. `TWITCH_CHANNEL` — это логин канала, как он выглядит в адресе
   `twitch.tv/<логин>` (только сам логин, без `twitch.tv/`).

## Шаг 3. (Опционально) Узнать ID канала YouTube

Если хотите оповещения и по YouTube тоже:

1. Откройте свой канал на YouTube → **Настройки** → **Дополнительные настройки**
   (или зайдите в YouTube Studio → Настройки → Канал → Основные), там указан
   **ID канала** вида `UCxxxxxxxxxxxxxxxxxxxxxxxx`.
2. Впишите его как `YOUTUBE_CHANNEL_ID`. Если оставить пустым — проверка
   YouTube просто не будет выполняться, бот будет следить только за Twitch.

### Про проверку YouTube

Официальный YouTube Data API даёт бесплатную квоту 10 000 единиц/день, а
поиск активных трансляций (`search.list`) стоит 100 единиц за запрос — при
проверке каждые 5 минут это 288 запросов/день = 28 800 единиц, что превышает
дневной лимит. Поэтому скрипт вместо этого читает публичную страницу
`youtube.com/channel/<ID>/live`, которая при начале эфира содержит ссылку на
активное видео — бесплатно, без ключа и без ограничений по квоте. Если
предпочитаете официальный API (например, ради надёжности), это несложно
заменить — скажите, и я перепишу этот кусок.

Раз вы стримите на YouTube и Twitch одновременно (симулькаст), проверки
Twitch обычно достаточно, чтобы понять, что трансляция началась — но
отдельная проверка YouTube даёт независимое оповещение с прямой ссылкой на
видео на YouTube, на случай если что-то пойдёт не по плану с одной из
площадок.

## Шаг 4. Выложить проект на GitHub

1. Создайте новый репозиторий на https://github.com/new.
   **Рекомендуется публичный репозиторий** — тогда GitHub Actions
   бесплатны без ограничений по времени. `state.json` содержит только
   технические флаги (live/не live), никаких токенов там нет — все
   секреты хранятся отдельно (см. следующий шаг) и в код не попадают.
   Если нужен обязательно приватный репозиторий — см. примечание в конце.
2. Загрузите в него все файлы из этого проекта, сохранив структуру папок
   (важно, чтобы `.github/workflows/check_stream.yml` остался по этому
   пути).

## Шаг 5. Добавить секреты в репозиторий

В репозитории: **Settings → Secrets and variables → Actions → New repository secret**.
Добавьте по одному:

| Имя секрета | Значение |
|---|---|
| `TELEGRAM_BOT_TOKEN` | токен бота из Шага 1 |
| `TELEGRAM_CHAT_ID` | chat_id канала из Шага 1 |
| `TWITCH_CLIENT_ID` | Client ID из Шага 2 |
| `TWITCH_CLIENT_SECRET` | Client Secret из Шага 2 |
| `TWITCH_CHANNEL` | логин Twitch-канала из Шага 2 |
| `YOUTUBE_CHANNEL_ID` | ID канала из Шага 3 (необязательно) |

## Шаг 6. Включить и проверить

1. Перейдите во вкладку **Actions** репозитория — если GitHub спросит,
   нажмите **I understand my workflows, go ahead and enable them**.
2. Откройте workflow **Check stream status** → кнопка **Run workflow** —
   это запустит проверку прямо сейчас, не дожидаясь расписания.
3. Откройте лог запуска и убедитесь, что нет ошибок. Если в это время вы
   были live на Twitch — в канал должно прийти сообщение.
4. Дальше всё работает само: проверка идёт каждые 5 минут.

## Ограничения и нюансы

- **Задержка**: GitHub Actions по `cron` не гарантирует запуск ровно
  вовремя — в пиковые часы возможна задержка в 1-5 минут сверх заданного
  интервала. Для оповещения о начале стрима это обычно некритично.
- **Бесплатные минуты**: в публичном репозитории Actions бесплатны без
  лимита. Если репозиторий приватный, бесплатный лимит — 2000 минут в
  месяц, а проверка каждые 5 минут расходует его целиком; в этом случае
  либо сделайте репозиторий публичным, либо увеличьте интервал в
  `check_stream.yml` (строка `cron: "*/5 * * * *"`) до, например,
  `*/15 * * * *` (раз в 15 минут).
- Если стрим идёт по 5 часов в день ежедневно, при проверке раз в 5 минут
  оповещение придёт максимум с задержкой в несколько минут после
  фактического начала эфира.

## Как поменять текст сообщения

Формат сообщений задан прямо в `stream_notifier.py`, в функции `main()` —
ищите переменную `text`. Можно менять текст, добавлять эмодзи, ссылки на
другие соцсети и т.п.
